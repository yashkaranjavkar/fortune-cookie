# Brag Document

## 2026-10-10 — Fortune Cookie (Fortunery)

Covers 2026-09-01 → 2026-10-10 (12 commits + uncommitted work).

- **Built** the core game from scratch: a fortune-cookie factory story where the player is hired as a Fortune Cookie Inspector, trains, then works through three levels of sorting and inspecting cookies (4 → 5 → 6 cookies) plus a supervisor checklist and a final tray-sorting round.
- **Architected** the game as self-contained, swappable sections (`gameFlow.js`), so a whole version of the game, such as the full story or a quick start, is changed by editing one array, with no code changes.
- **Designed** a consistent hand-drawn visual language across every screen (`theme.css`, design tokens, cookie and hand illustrations), including a custom cursor set (pointer, open hand, fist, highlighter, pen) with pressed states and @2x art.
- **Created** the game's sound world: ambient onboarding audio, footsteps while walking the factory, cookie cracks and highlighter strokes, all generated by a script (`scripts/make-sounds.js`) so they stay tweakable.
- **Added** a mascot that reacts to game events and places its pop-ups in whichever screen corner won't cover buttons, fields or drop targets.
- **Built** a separate analytics backend: a dependency-free Node + SQLite REST API with admin-token auth, CSV export, Docker deployment and end-to-end tests, plus a standalone analytics dashboard.
- **Shipped** a Chrome extension (Manifest V3) that, with the player's consent, builds a local profile of the sites they use (host names only) so fortunes can be personalised, and planned how personalised fortunes will be generated.
- **Moved** player details (Employee ID, designation, region) out of the game into a "connecting you to the game" onboarding, so players start the story faster.
- **Designed** cinematic room transitions: the camera follows the player across the factory map and zooms into the destination room, which then flies into the "Now entering" card's window and opens up into the next screen. Countdowns wait until the screen is actually visible, and there's a reduced-motion fallback. *(in progress)*
